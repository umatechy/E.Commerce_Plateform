IMPORTANT ARCHITECTURAL PRINCIPLE
---------------------------------
This project is one Core Multi-Tenant E-Commerce SaaS platform.
Basic, Business, and Premium are commercial packages/entitlements
within the same core platform. They are NOT separate codebases.

NON-NEGOTIABLE PRINCIPLES
-------------------------
1. Strict tenant isolation across database, API, files, cache, jobs,
   webhooks, search, analytics, exports, logs, and background workers.
2. Store/Tenant ID remains stable through package upgrades/downgrades.
3. Feature access is controlled by entitlements and usage limits.
4. Theme and branding are configuration-driven, not separate code copies.
5. Financial, security, authorization, and tenant-boundary operations
   must be server-authoritative.
6. No destructive database or production operation without explicit,
   verified authorization and a safe rollback/backup strategy.
7. Every implementation must include validation, testing, observability,
   auditability, and production-readiness checks.
8. Future expansion must be supported through stable extension points,
   adapters, events, versioned APIs, feature flags, and documented
   compatibility rules.

CLAUDE WORKFLOW
---------------
Phase A — Read:
- Read the complete Project Bible, URS, SRS and all 35 Module Blueprints.
- Treat them as the authoritative project specification.

Phase B — Inspect:
- Inspect the existing repository before modifying anything.
- Identify current stack, structure, dependencies, environment configuration,
  database schema, authentication, APIs, frontend/storefront, tests and
  deployment configuration.

Phase C — Reconcile:
- Detect conflicts, missing requirements, duplication and implementation gaps.
- Do not silently invent requirements.
- Document ambiguities and propose safe resolutions before implementation.

Phase D — Plan:
- Produce a dependency-aware implementation plan.
- Break work into milestones and atomic tasks.
- Define database, API, UI, background-job, security and test impacts.

Phase E — Implement:
- Implement incrementally.
- Preserve existing working functionality unless the specification requires
  a controlled change.
- Follow tenant isolation and server-authoritative rules everywhere.

Phase F — Verify:
- Run appropriate unit, integration, API, frontend, security, migration,
  regression and end-to-end tests.
- Run build, lint/static analysis and production-readiness checks.
- Fix failures rather than suppressing them.

Phase G — Checkpoint:
- Record completed work, files changed, migrations, tests, known issues,
  risks and exact next stopping point.
- Commit only coherent, verified work.
- Never claim completion without evidence.

PRODUCTION SAFETY
-----------------
- Never expose secrets in source control, logs, prompts, screenshots or
  generated documentation.
- Never bypass authorization or tenant checks for convenience.
- Never trust client-supplied prices, permissions, package entitlements,
  stock values or payment state.
- Use idempotency for retry-sensitive operations.
- Protect webhooks against forgery, replay and duplicate processing.
- Treat uploads, exports, imports and generated files as security-sensitive.
- Use safe migrations and explicit rollback planning.
- Financial and administrative operations require elevated authorization,
  audit trails and server-side validation.
