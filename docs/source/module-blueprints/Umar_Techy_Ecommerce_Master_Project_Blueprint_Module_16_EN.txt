1. MODULE PURPOSE
--------------------------------------------------------------------
Module 16 provides the Core SEO Engine and Content Management Engine
for the Umar Techy E-Commerce Platform.

The module controls tenant-scoped search engine optimization,
metadata, URL strategy, indexing directives, structured data,
social sharing metadata, sitemaps, robots directives, redirects,
static content, landing pages, blog/content foundations, content
blocks, publishing workflows, revisions, previews, scheduling,
multilingual content, internal linking, and SEO integrations.

The module must work across all tenants without sharing tenant-owned
content, URLs, metadata, indexes, media references, analytics
configuration, or SEO settings between stores.

The module is configuration-driven and must integrate with the
Storefront Engine, Catalog, Taxonomy, Customer/Marketing content,
Theme/Branding, Domain Management, Package Entitlements, Analytics,
and API layers.

Core principle:

ONE CORE SEO + CONTENT ENGINE
        +
TENANT SEO CONFIGURATION
        +
TENANT CONTENT
        +
TENANT DOMAIN / URL CONTEXT
        +
TENANT ENTITLEMENTS

No tenant-specific source-code forks are permitted.


2. PRIMARY OBJECTIVES
--------------------------------------------------------------------
The module shall:

1. Provide tenant-scoped SEO configuration.
2. Generate consistent metadata for storefront pages.
3. Support custom SEO metadata where permitted.
4. Provide deterministic canonical URL handling.
5. Manage SEO-safe slugs and URL changes.
6. Maintain redirect rules for changed URLs.
7. Generate XML sitemaps.
8. Generate robots directives and robots.txt output.
9. Support structured data / Schema.org foundations.
10. Support Open Graph and social sharing metadata.
11. Support image SEO and accessible alternative text.
12. Provide SEO controls for products, categories, collections,
    brands, pages, and content.
13. Provide static pages and configurable landing pages.
14. Provide content blocks and reusable sections.
15. Provide blog/article content foundations where entitled.
16. Support draft, review, preview, publish, schedule, unpublish,
    archive, and restore workflows.
17. Maintain content revisions and publishing history.
18. Support multilingual and RTL content foundations.
19. Support internal linking and breadcrumbs.
20. Handle pagination and duplicate-content risks.
21. Provide noindex/nofollow controls with safe defaults.
22. Support search-engine verification foundations.
23. Support analytics integration foundations.
24. Provide safe custom head/script insertion with strict controls.
25. Handle 404 and invalid URL behavior.
26. Prevent URL conflicts and tenant cross-contamination.
27. Expose secure APIs and events.
28. Enforce permissions and package entitlements.
29. Support caching, CDN, performance optimization, and observability.
30. Provide comprehensive security and automated testing.

6. TITLE GENERATION
--------------------------------------------------------------------
The engine shall support deterministic title templates.

Examples:

{product_name} | {store_name}
{category_name} | {store_name}
{page_title} | {store_name}

Supported tokens may include:

- store_name
- product_name
- category_name
- brand_name
- collection_name
- page_title
- site_name
- current_page
- total_pages

Rules:

1. Explicit page SEO title overrides generated title.
2. Missing variables must never produce broken markup.
3. Excessively long titles may produce an advisory warning.
4. Title generation must be tenant-scoped.
5. Template changes must not rewrite historical order snapshots.

8. SLUG MANAGEMENT
--------------------------------------------------------------------
Slugs must be:

- Tenant-scoped.
- URL-safe.
- Deterministic.
- Unique within the relevant URL namespace.
- Normalized.
- Reserved-word aware.
- Case-consistent.

Slug sources may include:

- Product name.
- Category name.
- Brand name.
- Collection name.
- Page title.
- Article title.

When a slug changes:

1. Existing URL must be preserved as a historical reference.
2. A redirect may be created automatically.
3. Redirect loops must be prevented.
4. Redirect chains should be collapsed where safe.
5. Existing canonical URL must be updated.
6. Sitemap output must use the current canonical URL.
7. Audit history must record the change.

Slug deletion must not silently orphan important URLs.

10. CANONICAL URL ENGINE
--------------------------------------------------------------------
Canonical URLs must be generated server-side.

The engine must support:

- Product canonical URL.
- Category canonical URL.
- Brand canonical URL.
- Collection canonical URL.
- Static page canonical URL.
- Article canonical URL.
- Pagination canonical strategy.
- Filter/sort canonical strategy.
- Query-string handling.

Default principle:

One indexable page should have one preferred canonical URL.

Canonical URLs must:

- Use the tenant's resolved public domain.
- Use HTTPS in production.
- Respect configured path rules.
- Avoid session/cart/query parameters.
- Avoid tracking parameters.
- Never point to another tenant unless explicitly configured
  through a controlled external canonical feature.

Self-canonical is the default for indexable pages.


11. INDEXING DIRECTIVES
--------------------------------------------------------------------
Supported directives:

- index.
- noindex.
- follow.
- nofollow.
- noarchive.
- nosnippet where supported.
- max-snippet where supported.
- max-image-preview where supported.
- max-video-preview where supported.

Safe defaults:

- Public product/category/content pages: index, follow.
- Cart: noindex.
- Checkout: noindex.
- Customer account: noindex.
- Internal search results: configurable, generally noindex.
- Admin routes: never public/indexable.
- Authentication routes: noindex.
- Error pages: noindex.

Store suspension/maintenance states must be handled safely and
must not accidentally expose private administrative content.


12. ROBOTS.TXT
--------------------------------------------------------------------

Default disallowed areas may include:

/admin/
/account/
/cart/
/checkout/
/api/

The exact rules must be configurable only through authorized
settings.

The engine must prevent:

- Invalid syntax.
- Cross-tenant URLs.
- Accidental exposure of private paths.
- Blocking the entire storefront unintentionally without warning.

Robots.txt must not be treated as a security boundary.

--------------------------------------------------------------------

- Custom 404 page.
- Missing product handling.
- Missing category handling.
- Missing content handling.
- Expired landing page handling.
- Redirect lookup.

Rules:

2. Otherwise return a correct 404.
3. Do not redirect every missing URL to homepage.
4. 404 pages must not be indexable.
5. Redirect loops must be prevented.
6. Redirect chains should be monitored.

46. DATA INTEGRITY RULES
--------------------------------------------------------------------
1. Tenant ID must be immutable for tenant-owned records.
2. Slugs must be unique within the correct tenant namespace.
3. Published content must have a valid public route.
4. Indexable content must have a resolvable canonical URL.
5. Sitemap entries must reference eligible URLs only.
6. Redirect source and destination must be normalized.
7. Redirect loops must be rejected.
8. Redirects must not expose private tenant paths.
9. Draft content must never leak into normal public rendering.
10. Revision restore must be transactional.
11. Scheduled publishing must be idempotent.
12. Deleted content must not remain accidentally indexable.
13. Cross-tenant references must be rejected.
14. Locale references must be valid.
15. Custom code must have appropriate authorization.
16. Historical revisions must remain auditable.

59. FINAL ARCHITECTURAL RULES
--------------------------------------------------------------------
RULE 01:
Module 16 is tenant-scoped.

RULE 02:
SEO metadata is never a source of truth for catalog, inventory,
orders, payments, or customer financial data.

RULE 03:
Canonical URLs are server-generated and tenant-aware.

RULE 04:
Client-supplied canonical, price, availability, or structured-data
values must never override authoritative business data.

RULE 05:
Historical URLs should be preserved through redirects where
appropriate.

RULE 06:
Robots.txt is not a security mechanism.

RULE 07:
Noindex is not a substitute for authentication/authorization.

RULE 08:
Draft content must never become public accidentally.

RULE 09:
Preview access must be temporary and authorized.

RULE 10:
Custom HTML/JavaScript is privileged functionality.

RULE 11:
All rich content must be sanitized.

RULE 12:
All public URLs must resolve within the correct tenant context.

RULE 13:
Sitemap output must contain only eligible canonical URLs.

RULE 14:
Content changes must invalidate affected caches.

RULE 15:
Package entitlements control premium SEO/content capabilities.

RULE 16:
One core codebase serves all packages.

RULE 17:
No tenant may read or write another tenant's SEO/content data.

RULE 18:
SEO diagnostics are advisory and never promise search rankings.

RULE 19:
All publishing, redirect, SEO configuration, and privileged
content actions must be auditable.

RULE 20:
Module 16 must integrate with the rest of the platform through
defined contracts, events, APIs, and authoritative module ownership.
