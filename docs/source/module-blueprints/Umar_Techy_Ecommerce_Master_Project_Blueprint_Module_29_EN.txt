2. CORE ARCHITECTURAL PRINCIPLES
------------------------------------------------------------

2.1 One Core Billing Engine

All platform billing must use one Core Billing Engine.

Do not create separate billing engines for:

- Basic.
- Business.
- Premium.
- Resellers.
- Hosting.
- Domains.
- Add-ons.
- Marketplace extensions.

Commercial behavior must be configuration-driven.

2.2 Multi-Tenant by Design

Every tenant billing account, subscription, invoice, credit,
payment reference, billing profile, and usage record must be
tenant-scoped unless explicitly platform-level.

Tenant resolution must occur before tenant-owned billing data is
accessed.

2.3 Server Authority

The server is authoritative for:

- Package price.
- Subscription amount.
- Billing interval.
- Discount.
- Tax.
- Credit.
- Invoice total.
- Renewal date.
- Proration.
- Payment state.
- Subscription state.
- Usage charge.
- Reseller price.
- Add-on price.

Client-provided financial values must never be trusted.

2.4 Immutable Financial Documents

Issued invoices and credit notes must be immutable.

Corrections must use:

- Credit notes.
- Debit adjustments.
- Replacement invoices.
- Reversal records.
- Authorized adjustment records.

Do not silently rewrite historical issued documents.

2.5 Separation of Subscription and Payment

Subscription state describes commercial service access.

Payment state describes financial collection.

Invoice state describes the financial document.

These must remain separate.

2.6 Entitlement Separation

Module 04 determines what the store is entitled to use.

Module 29 determines what the store is billed for.

Module 29 may trigger entitlement changes through approved
interfaces, but must not duplicate entitlement logic.

33. FAILED PAYMENT HANDLING
------------------------------------------------------------

When renewal payment fails:

1. Mark payment attempt failed.
2. Keep invoice unpaid/past due as applicable.
3. Retry according to configured schedule.
4. Notify customer.
5. Enter grace period where configured.
6. Restrict entitlements according to Module 04.
7. Suspend if grace period expires.
8. Preserve all records.

Do not immediately delete customer data.
