1. MODULE PURPOSE
--------------------------------------------------------------------
Module 22 provides the Core Reporting, Analytics, Metrics,
Dashboards, Business Intelligence, Usage Reporting, and Data
Visualization foundation for the Umar Techy Multi-Tenant
E-Commerce Platform.

The module transforms authoritative platform events and business
data into tenant-scoped operational reports, dashboards, analytics,
KPIs, trends, exports, scheduled reports, and platform-level
analytics.

The system must support:

- Store dashboards.
- Platform/Super Admin dashboards.
- Sales analytics.
- Order analytics.
- Product analytics.
- Customer analytics.
- Inventory analytics.
- Marketing analytics.
- Payment analytics.
- Shipping analytics.
- Communication analytics.
- Subscription/package analytics.
- Domain/infrastructure usage analytics.
- SEO/content analytics.
- Theme/interaction analytics.
- AI usage analytics.
- Financial reporting foundations.
- Custom report foundations.
- Scheduled reports.
- Data exports.
- Comparative analysis.
- Forecasting foundations.
- Near-real-time metrics.
- Historical reporting.
- Tenant-safe analytics.

Core principle:

AUTHORITATIVE SOURCE DATA
        +
TENANT-SCOPED ANALYTICS PIPELINE
        +
STANDARDIZED METRICS
        +
REPORTING LAYER
        +
DASHBOARD PRESENTATION
        +
SECURE EXPORTS

Analytics must never become a second source of truth for
transactional business state.

74. FINAL ARCHITECTURAL RULES
--------------------------------------------------------------------
RULE 01:
Module 22 owns reporting and analytics, not transactional business
truth.

RULE 02:
Source modules remain authoritative for their business states.

RULE 03:
Every analytics event must preserve tenant context where applicable.

RULE 04:
Analytics data must never cross tenant boundaries.

RULE 05:
Every metric must have a documented definition.

RULE 06:
Financial metrics must define their accounting basis.

RULE 07:
Currency must never be mixed without explicit conversion.

RULE 08:
Store dashboards must use store timezone by default.

RULE 09:
Platform dashboards must apply platform-level authorization.

RULE 10:
Customer-level analytics require elevated permission.

RULE 11:
Analytics must minimize personal data.

RULE 12:
No arbitrary SQL access is permitted through custom reports.

RULE 13:
Report exports must be tenant-scoped and access-controlled.

RULE 14:
Temporary export files must expire.

RULE 15:
Analytics cache keys must preserve tenant identity.

RULE 16:
Heavy reports must execute asynchronously.

RULE 17:
Analytics failures must not stop storefront, checkout, orders, or
payments.

RULE 18:
Event ingestion must be idempotent.

RULE 19:
Aggregation jobs must be idempotent.

RULE 20:
Late and duplicate events must be handled safely.

RULE 21:
Data freshness must be transparent where relevant.

RULE 22:
Analytics must be periodically reconciled against authoritative
transactional data.

RULE 23:
Attribution is analytical and must never rewrite financial order
data.

RULE 24:
Package entitlements control advanced analytics capabilities.

RULE 25:
Infrastructure execution belongs to Module 20.

RULE 26:
Communication delivery belongs to Module 21.

RULE 27:
Marketing strategy belongs to Module 15.

RULE 28:
Billing truth belongs to Module 29.

RULE 29:
Security/compliance policy belongs to Module 32.

RULE 30:
Module 22 must integrate through explicit event contracts, APIs,
schemas, permissions, aggregation pipelines, and authoritative
ownership boundaries.
